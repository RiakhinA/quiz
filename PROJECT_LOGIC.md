- Production: https://riakhin-quiz.vercel.app/

- Деплой: GitHub → Vercel.

## 2. Главная задача сайта
Провести человека через квиз, дать персональную карту/инсайты и мягко привести к следующему действию: записаться на разбор или связаться с Антоном.

30 бесплатных минут НЕ являются общим публичным оффером. Это бонус/следующий шаг для человека, прошедшего «Карту выхода». На отдельном будущем сайте обычной записи основной продукт — полноценная консультация.

## 3. Основной пользовательский путь
1. Вход на сайт.
2. Прохождение вопросов квиза.
3. Получение результата / карты.
4. CTA после результата.
5. Экран записи.
6. Пользователь может:
   - оставить имя и телефон;
   - выбрать удобное время;
   - написать Антону напрямую в соцсети/мессенджер.
7. При выборе времени:
   - выбрать день;
   - выбрать слот;
   - либо нажать «Не нашли удобного времени?» и написать свой вариант;
   - добавить необязательный комментарий «Что вам важно сказать?»;
   - перейти к выбору способа связи.
8. После выбора времени человек либо отправляет заявку с контактами, либо открывает чат с Антоном.

## 4. Логика экранов записи
### Экран 1 — запись
- Имя.
- Телефон, если удобно.
- Кнопка «Выбрать удобное время».
- Альтернатива: сразу открыть Instagram или Telegram.

### Экран 2 — выбор времени
- Сегодня / завтра / другой день.
- Слоты времени.
- «Не нашли удобного времени? Напишите свой вариант — что-нибудь придумаем».

### Экран 3 — комментарий
После выбранного слота НЕ спрашивать день повторно.
Показывать выбранное время.
Поле: «Что вам важно сказать?» — тема, пожелание или информация перед встречей; необязательное.

Если человек выбрал «Не нашли время», сначала отдельное свободное поле для желаемого дня/времени, затем тот же комментарий.

### Экран 4 — способ связи
Вариант 1: имя + телефон + выбор, куда Антону написать для подтверждения (Telegram / WhatsApp / Viber / Instagram). Не обещать звонок как основной способ.

Вариант 2: пользователь сам открывает удобный чат/соцсеть и пишет Антону.

При клике на соцсеть/мессенджер заявка/событие должно фиксировать выбранное время, комментарий и канал связи до открытия внешнего чата.

## 6. Готовое сообщение при переходе в чат
Базовый смысл: «Хочу записаться на разбор» + выбранные день/время + комментарий пользователя, если он есть.

Не делать «бесплатные 30 минут» главным текстом сообщения или публичным главным оффером.

Техническое ограничение: не каждый внешний сервис одинаково поддерживает предзаполненный текст из обычной веб-ссылки. Где это невозможно, текст можно подготовить/скопировать, а чат открыть отдельно.

## 7. Передача заявок
Endpoint: `/api/send-lead`.

Заявка должна по возможности содержать:
- имя;
- телефон/контакт;
- язык;
- ответы квиза;
- UTM;
- выбранную дату;
- выбранное время;
- свободный вариант времени;
- комментарий;
- способ/канал связи;
- режим: форма или клик по соцсети.

## 8. Аналитика
Используются GA4 и Meta Pixel.

Нужно различать минимум:
- отправку формы;
- выбор/клик канала связи;
- прямой переход в соцсеть;
- выбранное время;
- пользовательский вариант времени.

Социальный переход считается отдельным лид-действием даже без оставленного телефона, если перед открытием чата удалось отправить событие/lead payload.

## 9. Автоматические ответы / тексты
На текущем сайте автоматический ответ внутри внешнего Instagram/Telegram не создаётся самим HTML. Сайт формирует контекст заявки и открывает канал связи.

Будущая SendPulse-автоматизация ведётся отдельно: запрос про консультацию → предложить записаться либо продолжить разговор/задать вопрос в Instagram. Для отдельного сайта записи в начале предполагается выбор между полноценной консультацией и, только для прошедших карту, бонусным 30-минутным разбором.
